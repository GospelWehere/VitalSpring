1. The Project in 60 Seconds

Opening answer

Vital Spring Medical Center is treated as a medium-sized Nigerian outpatient facility that currently relies on paper folders, handwritten registers and a physical appointment book. The proposed Clinic Appointment System replaces the fragmented process with a secure browser-based service for patient registration, practitioner availability, appointment booking, patient check-in, live queue coordination, visit documentation, reminders and management reporting.

Core problem

  • Paper records are disconnected and easily lost.
  • Double-booked slots and missing files.
  • No automatic reminders or dependable statistics.
  • No accountable access to sensitive information.

Core value

  • One source of truth for patients and slots.
  • Live queue tracking reduces waiting times.
  • Automated confirmations and reminders.
  • Measurable attendance, wait and utilisation.

6. Strongest Technical Defense

How double-booking is prevented

  1. The interface displays only open, future slots.
  2. The server locks the selected slot, rechecks its status and reserves it inside one database transaction.
  3. A unique constraint (unique slot_id on active appointment) permits only one appointment per slot.
  4. If two users confirm simultaneously, one commit succeeds; the other rolls back and receives available alternatives.
BEGIN;
SELECT status FROM availability_slot
WHERE id = :slot_id FOR UPDATE;
-- application checks status is 'open'
INSERT INTO appointment (slot_id, patient_id, ...)
VALUES (:slot_id, :patient_id, ...);
UPDATE availability_slot SET status = 'reserved'
WHERE id = :slot_id;
COMMIT;

7. Architecture, Security and Recovery

Four access channels

  • Patient portal: self-service booking and history
  • Front desk: registration, booking, check-in
  • Clinical: queue, history, visit records
  • Management: reports, accounts, activity review

Security controls

  • HTTPS in transit; encryption at rest
  • Strong password hashes + MFA for privileged roles
  • Role-based, minimum-necessary access
  • 15-minute staff inactivity timeout
  • Append-only activity log
  • Daily encrypted backups + quarterly restoration

Privacy wording

The design follows the Nigeria Data Protection Act 2023 and professional confidentiality principles. It is a classroom system proposal, not a claim of legal certification.

8. Implementation and Testing

Phases: confirm requirements → prototype → build → test → prepare data → train → pilot → deploy → review at 22, 30 and 90 days.

Critical tests: simultaneous slot booking; role bypass; invalid registration; duplicate detection; reminder retry; report reconciliation; 25-user performance; backup restoration within four hours.

Downtime: printed next-day appointment list + numbered downtime sheets; one-person back-capture and second-person verification after recovery.

9. Answer Formula

Define → Apply → Justify → Example.

"Cardinality states how many instances may relate. In Vital Spring, one patient can have many appointments, but each appointment has exactly one patient. This models repeat visits while preventing an unidentified appointment."

Closing answer

Vital Spring is technically, economically and operationally feasible. It replaces disconnected paper processes with a secure, auditable workflow that prevents scheduling conflicts, tracks live patient flow, reduces no-shows and gives management reliable attendance and waiting-time information.
